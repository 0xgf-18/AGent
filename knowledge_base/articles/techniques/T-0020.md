# Technique T-0020: Packed-APK baseline verification gate (shell-dex triage)

## This Article Answers
- "How do I packed-apk baseline verification gate (shell-dex triage)?"
- "When does technique T-0020 apply?"
- "What are the prerequisites for T-0020?"

## Key Takeaways
- [PROBLEM] Before any unpack attempt, prove the packed APK is a healthy signed container and prove its plaintext dex is a shell (loader classes present, app classes absent), with multi-category verification - this separates real packer state from corrupt/forged inputs and yields the baseline for before/after comparison.
- [PREREQUISITES] tools TR-0007, TR-0009, TR-0011, TR-0012; root=False; env host filesystem access, python stdlib
- [WORKFLOW] python -c "import zipfile; z=zipfile.Zip -> python .kb/scripts/verify_result.py pars -> python .kb/scripts/verify_result.py cont -> zipalign -c -p 4 + apksigner verify + sh
- [VERIFICATION] 5-category gate (STRUCTURAL/PARSER/CONTENT/DOWNSTREAM/REPRODUCIBILITY); VERIFIED_SUCCESS only at >=3 distinct categories with zero FAIL
- [CONFIDENCE] 0.7 (CANDIDATE)

## Problem Statement
- Protection class addressed: `any packer with shell dex (proven on 360 jiagu 1.5)`
- Why standard approaches fail: COMMAND_SUCCESS alone accepts corrupt dex or mis-probed content; without >=3 gate categories a single flaky check can fake success.
- Applicable when: single small classes.dex (<100 KB) vs large APK; loader/protector namespace in dex (com.qihoo.*, libSecShell, Bangcle, VMP markers); app package classes absent from plaintext dex; encrypted payload files in assets/ (ProtectV1/V2/V3.zip, jiagu assets)

## Workflow

### Step 1: Extract shell dex
**Observation:** fingerprint reports 1 small dex + packer assets
**Action:** python -c "import zipfile; z=zipfile.ZipFile('<apk>'); open('classes.dex','wb').write(z.read('classes.dex'))"
**Tool:** TR-0011
**Expected Result:** 43-44 KB stub dex written
**Success Indicator:** extracted size < 100 KB and file exists
**Failure Mode:** KeyError/zip error -> APK structure differs, re-fingerprint
### Step 2: Validate DEX header
**Observation:** shell dex extracted
**Action:** python .kb/scripts/verify_result.py parser --dex classes.dex
**Tool:** TR-0012
**Expected Result:** PASS - magic/size/adler32/sha1 ok, string_ids > 0
**Success Indicator:** parser exit 0 with non-zero string/type counts
**Failure Mode:** checksum mismatch -> corrupted shell, treat as ENVIRONMENT/APK issue
### Step 3: Probe shell vs app content
**Observation:** header valid, need packer identification
**Action:** python .kb/scripts/verify_result.py content --file <apk> --class <loader_class> and --class <app_class>
**Tool:** TR-0009
**Expected Result:** loader class PASS, application class FAIL
**Success Indicator:** qihoo/libSecShell-style class present AND app class absent = packed state confirmed
**Failure Mode:** app class present -> NOT packed; abort technique (prereq not met)
### Step 4: Package + reproducibility checks
**Observation:** packed state confirmed, baseline needed
**Action:** zipalign -c -p 4 + apksigner verify + sha256 vs fingerprint, then python .kb/scripts/verify_result.py gate r1.json ... r6.json
**Tool:** TR-0007
**Expected Result:** gate VERIFIED_SUCCESS (>=3 categories, zero FAIL)
**Success Indicator:** gate exit 0 = VERIFIED_SUCCESS, baseline sha locked
**Failure Mode:** exit 10 = COMMAND_SUCCESS only, exit 1 = FAILED; never learn from <3 categories

## Decision Points
| Decision Point | Condition | If True | If False |
|---|---|---|---|
| DP1 | app class probe FAIL (absent) | continue - packed state confirmed | abort - APK not packed, technique not applicable |
| DP2 | gate >=3 categories PASS | VERIFIED_SUCCESS, record baseline | COMMAND_SUCCESS - do not record as learned success |

## Success Indicators
- parser PASS with string_ids > 0 on shell dex
- loader class present AND app class absent
- gate returns VERIFIED_SUCCESS across >=3 categories with zero FAIL
- input sha256 stable across repeated runs

## Verification Method
### Structural
- zip CRC of all entries -> no bad CRC

### Content
- loader class present -> PASS
- application class absent -> PASS (expected negative)

### Parser
- DEX header adler32/sha1 match -> PASS

### Downstream Analysis
- zipalign -c 4 + apksigner verify -> both pass

### Reproducibility
- sha256 stable vs fingerprint across re-runs

**Final Status:** COMMAND_SUCCESS vs VERIFIED_SUCCESS (only VERIFIED_SUCCESS counts for learning)

## Known Failure Conditions
| Condition | Symptom | Workaround |
|---|---|---|
| app class probe returns PASS (class found in plaintext dex) | APK not actually packed | skip unpacking, analyze plaintext directly |
| parser checksum mismatch on extracted dex | stored != calculated adler32 | re-extract; if persistent classify ENVIRONMENT_ISSUE/APK_FAILURE |
| apksigner verify fails | DOWNSTREAM category FAIL | gate yields COMMAND_SUCCESS only - record as APK failure, not technique failure |

## Limitations
- host-only: proves packed state and container health but does NOT unpack the payload
- class-probe relies on knowing one real app class name from badging/manifest heuristics
- proven on 360 jiagu (pokemon.dex.guard 1.5) only - other packers untested (evidence: 1 APK)
